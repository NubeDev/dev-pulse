# dev-pulse

**dev-pulse** is a GitHub reporting and insights tool for tracking developer activity,
workload, and output across multiple organisations. This is the **end-user guide** — how
to use the product once it's running.

These pages cover the **Projects** surface first (the portfolio report, creating and
managing projects, milestones, the issue workbench, and linking GitHub boards/repos).
More sections will land here as the product grows.

## Start reading

- **[Projects introduction](/projects/introduction)** — what a project is and where to find it.
- **[Project portfolio](/projects/portfolio)** — the cross-org report at
  `#/reports/projects`: which projects are on track, slipping, or done.
- **[Create a project](/projects/create)** — name, org, dates, lead.
- **[Project detail page](/projects/detail)** — KPI tiles, tabs, and the Settings menu.
- **[Milestones](/projects/milestones)** — the milestones strip, GitHub write-through.
- **[Issue workbench](/projects/workbench)** — grouping, filters, sort, and saved views.
- **[Link boards &amp; repos](/projects/link-boards-repos)** — connect GitHub Projects boards
  and repos to a project.

## Conventions used here

- **Routes** are written as hash routes (e.g. `#/reports/projects`) — that's what you'll
  see in your browser's address bar.
- UI labels are written **in bold** the way they appear in the product (e.g. the
  **+ New project** button).
- Test-ids and internals are left out on purpose — this guide is for people using
  dev-pulse, not building it.
